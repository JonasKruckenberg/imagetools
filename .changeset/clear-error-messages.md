Improve error messages for easier debugging

- Invalid directive values now throw an actionable error instead of being silently ignored. This applies to numeric directives (`w`, `h`, `aspect`, `rotate`, `quality`, `effort`, `hue`, `saturation`, `brightness`, `blur`, `median`), enum directives (`format`, `fit`, `kernel`, `position`), boolean directives (`flip`, `flop`, `grayscale`, `invert`, `normalize`, `flatten`, `progressive`, `lossless`, `allowUpscale`) and `basePixels` when generating density descriptors (`srcset`, `img` and `picture` output formats). Validation runs when the transform is applied, so e.g. `?fit=bogus` is rejected when a width is given and `?format=webp&quality=abc` rejects the `quality` value. `w` and `h` must be positive, `quality` an integer between 0 and 100, `blur` a sigma between 0.3 and 1000 and `median` a size between 1 and 1000. The error quotes the offending value and lists what was expected, e.g. `Invalid fit value: "bogus", expected one of "cover", "contain", "fill", "inside" or "outside"`. Every directive accepts `"false"` as a no-op that disables the transform, so a directive applied through `defaultDirectives` (or any other default configuration) can be turned off for a single image with e.g. `?format=false`, `?blur=false` or `?w=false`. An empty `format` value — e.g. the trailing segment of `?format=avif;webp;png;` — is rejected by the `format` transform with the same error as any other unsupported value. The `format` directive is validated against the full list of formats sharp accepts (including aliases like `jpg`, `tif` and `heic`), so a mistyped value such as `?format=jepg` is rejected instead of being passed to sharp, which would only fail later with a less helpful error.
- Integer directives no longer silently truncate fractional values. Values like `quality=3.5` or `w=300.75` that were previously truncated are rejected instead, so a mistyped directive surfaces as an error rather than producing an unexpectedly sized or compressed image. `quality=0` is accepted and recorded, but falls back to sharp's default quality since sharp rejects a quality of 0 for most formats.
- The `noAutoOrient` directive reports which values are valid when given an unexpected value.
